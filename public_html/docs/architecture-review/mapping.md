## Join contracts for the migration

| Relationship | Observed evidence | Safe canonical join and cardinality | Reject/review condition |
|---|---|---|---|
| Student across registration, dues, attendance, tasks | CCA code in registration D; attendance E; MASTER student code derived by lookup | Canonical student ID with unique source code and correct unit; student 1:N enrollments, tasks and ledger entries | Missing/reused code, code/name contradiction, wrong team; no name-only fallback. |
| Teacher across HR, sales, assignments, hours | CT code in HR D; source attendance C; MASTER C; teacher-name lookups in sales | Canonical teacher ID; teacher 1:N capabilities/enrollments; current app 0:1 unit membership | Conflicting CT identities, stopped teacher autoactivation, mismatched ownership. Phone/name may propose a match, not prove it. |
| Candidate → teacher | HR applications lack CT in many early stages; registration has CT | Candidate 1:N source responses/interviews, reviewed optional teacher link | Shared family phone, changed phone/name, conflicting CT. Keep source record even when canonical identity merges. |
| Lead → demo → student | Sales code/phone/name + demo outcomes; imported student registration | Lead 1:N demo attempts; lead optional canonical student; retain attempt history | Two children share a phone; repeated/rejoined enquiry; missing conversion evidence. |
| Teacher + student → enrollment | MASTER pairing, rate fields; timetable/marklist subject | Enrollment requires student, teacher, subject, unit and validity interval | Multiple subjects/assignments on same pair; missing effective date; source pair alone cannot resolve. |
| Enrollment → timetable → lesson | Weekday blocks, times, duration, reschedule | Enrollment 1:N dated agreements; agreement 1:N occurrences; optional replacement links | Ambiguous local time/DST, overlap, old version, cancellation, orphan replacement. |
| Source attendance → lesson | DATA A source ID; C CT; E CCA; F date; G hours | One active attendance per lesson; immutable source mapping; date/teacher/student are corroboration | More than one candidate lesson; source ID collision; negative/invalid hours; duplicate import of monthly archives. |
| Attendance → bill/payable | Hours × separate student/teacher rates | Distinct event keys for student charge and teacher accrual; compensating reversals, exact rounding | Wrong rate period, pre-cutoff replay, unreviewed duplicates, parent/admin gate not met. |
| Receipt → student/account/document | Accounts Ledger invoice reference, student code, credit/debit, account | Payment is its own event. Proposed allocation N:M to invoices; requests already have allocation table | Missing source transaction ID, two currencies mixed, reversal ambiguity, copied invoice template, duplicate receipt reference. |
| Assessment → enrollment | CT/CCA/subject/chapter/date + mark/max/mode | Enrollment 1:N assessments; independent submission ID | Ambiguous enrollment, impossible score/max, same submission replay with changed payload. |
| Task → staff/student/template | Task source label, CCA in text, checklist, `New Task ` | Staff ID + optional student/teacher IDs; template version; immutable task/source ID | Emoji/label is not a user ID; changed completion date must not create a task; backup/current duplicate. |

## Important formula observations

- VIEW TEACHER `Form responses 1!A1` imports HR `A:W`; subsequent blocks import other noncontiguous HR columns. Therefore “same column number” across the two sheets is not a safe mapping.
- Master 2025 `Master!E4` and EXAM RESULTS `MASTER!E4` resolve student codes through **student-name** VLOOKUP. Same names can silently bind to the first match. A full collision profile is required; this review does not claim observed names are unique or duplicated.
- Student registration `Form responses 1!CX3` imports a monthly-hours column from Master 2025 `ADVANCE SOP!DT5:DT`. It is a positional import, not an explicit CCA-keyed join. Reordering/filter changes require reconciliation.
- Sales `DEMO STATUS!T4/U4` look up teacher name in imported HR data. Matching must move to teacher IDs/codes while preserving the source labels for audit.
- HR `TIME TABLE!A1` reads TT 2025, while `AL1` reads TT new Vers 5. That mixed dependency needs version/effective-date review.
- Task `✅AA 2.0!J1` awards points only for completed tasks and applies a quantity/base-value rule. Importing one observed point value as a permanent template default is not equivalent.
- Source examples include `#REF!` in teacher/assignment/projection cells and `#DIV/0!` in performance summaries. Treat invalid source formulas as exceptions; zero is not an equivalent replacement.

## Source authority after cutover

The user confirmed application authority for attendance and payments, with Sheets retained as read-only history/exports. The attendance and money rows below implement that decision; the other entity-level assignments remain architectural recommendations. This is a source-ownership decision, not evidence that cutover or reconciliation has occurred. See [source-authority.md](source-authority.md).

| Fact | Authoritative store (confirmed for attendance/payments; proposed for other facts) | Derived views |
|---|---|---|
| Person identity | Canonical students/teachers plus reviewed external identity map | Sales/HR/admin directories |
| Recruitment | Shared candidate, source responses and linked interview/events | Available teacher directory |
| Teacher capabilities and availability | Verified eligibility, matching profile, dated availability/exceptions | Subject teacher lists, allocation suggestions |
| Assignment and schedule | Enrollment + accepted agreement + dated lesson | AA/BB timetables, first-class queues |
| Delivered class | Lesson-linked attendance with review history | DAYWISE/monthly hours and duplicate queues |
| Money and teacher payable | Immutable ledger events with proven receipt/source IDs | Dues, low-fee queues, salary summaries |
| Invoice | Issued invoice snapshot + lines + allocations, once implemented | Invoice templates and printable statements |
| Work management | Versioned templates, canonical tasks/items and actor IDs | Performance/points dashboards |

Retain legacy workbook snapshots as evidence and reporting exports. Do not permit unsupervised bidirectional writes to both systems for the same fact.
